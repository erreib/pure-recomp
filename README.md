# pure-recomp

A native macOS (arm64) build of **Wipeout Pure** (PSP, Studio Liverpool, 2005) by static recompilation. The game's
MIPS Allegrex code is translated to C++ ahead of time and runs against a rewritten PSP OS layer; the PSP graphics
engine is replaced by a native Metal backend, the default on macOS (D-008), and the Vulkan backend (through MoltenVK)
that bootstrapped the port stays as the portable path. You need your own dump of the US Greatest Hits disc
(UCUS-98612, v2.00, ISO CRC32 4502C588). Nothing from the game is in this repo.

## Play
`tools/bundle.sh` builds `out/release-macos/stage/Wipeout Pure.app` (a Release build, then the framework's packer:
the app with its libraries, licences and icon, signed ad hoc, no game data). Open it from Finder; the first start asks
for your disc image and sets the game up in `~/Library/Application Support/pure-recomp/PureNative/`, where the saves
live too (as of 2026-10-06 the setup stops at preparing the executable, because the profile names the encrypted
EBOOT.BIN without its key: docs/release.md, "First run: the setup"). How to build and bundle, what the app holds,
the setup, the data directory, the Vulkan path from the app and `tools/bundle.sh --check`:
[docs/release.md](docs/release.md). The player's read-me is `packaging/macos/README.txt`.

Framework: the MIT [PSPRecomp](https://github.com/jessicanataliagta/PSPRecomp) lineage as carried by
[TeamGDB/Yakumo](https://github.com/TeamGDB/Yakumo), vendored at a pinned commit under `vendor/` and modified
through the numbered series in `patches/`. Our game profile lives in `src/` and is synced into the vendor tree.

## First-time setup
```
brew install cmake ninja ccache pkgconf sdl3 molten-vk vulkan-loader vulkan-headers glslang vulkan-validationlayers ghidra
brew install --cask ppsspp-emulator
ln -s "/path/to/Wipeout Pure (USA) (En,Fr,Es) (v2.00).iso" disc.iso
python3 tools/iso_extract.py disc.iso verify && python3 tools/iso_extract.py disc.iso extract disc
tools/check_env.sh
```
Details and machine traps: [docs/setup.md](docs/setup.md). Ghidra: `tools/ghidra_headless.sh import` then `export`.

## Running
`tools/setup_game.sh` lays out `game/` (EBOOT.ELF = the disc's plain BOOT.BIN, `disc.iso`, `ms0/`). `tools/regen.sh`
generates the corpus into `generated/` (85 s) and `tools/build.sh profile` compiles it (8 min cold, seconds after).
`build/arm64/bin/PureNative` runs the game; `tools/run_boot.py` wraps it with a deadline and a folded log. The game
runs under a pty, so a deadline kill loses no output, and the log always ends with the `[run_boot] exit` line.
What a player presses (the keyboard's two layouts, the mouse, the gamepad, rebinding in the Esc menu and in
settings.ini) is in [docs/controls.md](docs/controls.md).

| `tools/run_boot.py` flag | Meaning |
|---|---|
| `--seconds N` | wall-clock deadline, default 60; exit code 124 when it kills the game |
| `--window` | renderer on (headless otherwise: `PURE_NO_RENDER=1`); the shell and backend are the default ones (Metal on macOS) unless named. Silent all the same unless `--sound` (task 034) |
| `--shell vulkan\|metal\|headless` | (task 028) `PURE_SHELL`. `vulkan` and `metal` imply `--window`. `headless` keeps the run headless even with `--script` or `--shots`, sets `PURE_GE_BACKEND=null` unless `--backend` or the environment names a backend; the run is unpaced: `--shell headless --script config/pad_scripts/frontend.txt --shots DIR --frames 2200` reaches the profile screen in about 1 s with the four shots written (black, from null; `--backend metal` draws them) |
| `--backend NAME` | (task 028) `PURE_GE_BACKEND` (`metal`, `vulkan`, `null`, `record`) |
| `--strict` | `PURE_STRICT_HLE=1` |
| `--frames N` | `PURE_EXIT_AT_FRAME=N`, deadline at least N/15 s, exit code 0 when the run ends at that frame |
| `--script FILE` | `PURE_INPUT_SCRIPT` from the file's non-empty, non-`#` lines joined with `;`; implies `--window` unless `--shell headless` (which runs the script without a window) |
| `--shots DIR` | `PURE_SCREENSHOT_DIR`; implies `--window` unless `--shell headless`; after the run each new BMP there gets a PNG beside it (`tools/png.py`) |
| `--every N` | `PURE_SCREENSHOT_EVERY` (default 0 with `--shots`: only the script's `shot` steps write) |
| `--stubs` | `<log>.stubs.txt`: the start-up "Unimplemented imports" list and each `[hle-stub]` call with its `ra` |
| `--sound` | (task 034) the audio device on. Without it every run is silent (`PURE_NO_AUDIO=1`) unless the environment (or `--env`) sets `PURE_NO_AUDIO`, or sets `PURE_AUDIO_WAV` in a window run (task 013's checks; the capture wraps the game's sceAudio calls, which run with or without the device) |
| `--data-dir DIR` | (task 034) `PURE_DATA_DIR` (settings.ini, pipeline caches, logs, save backups), default `out/data/run_boot`, unless the environment (or `--env`) names one: made on first use with a `settings.ini` holding `ui.menu_hint_seen=1` and kept between runs, so a test run never reads or writes the player's `~/Library/Application Support/pure-recomp/PureNative/` and settings changed while playing never reach a test. `frame_regress.sh`, `hud_check.sh`, `save_roundtrip.sh` and `campaign_sweep.py` each pass their own, `out/data/<tool>` |
| `--max-lines N`, `--env K=V` | log cap (default 20000); any extra environment variable, applied last |

| Switch | Meaning |
|---|---|
| `PURE_NO_RENDER=1 PURE_NO_AUDIO=1` | headless and silent (what `tools/run_boot.py` sets unless `--window`; since task 034 it sets `PURE_NO_AUDIO=1` with a window too, unless `--sound`): the headless shell, in which the default Metal backend still draws (on the GPU, unpaced); with `PURE_GE_BACKEND=vulkan` no rendering at all |
| `PSPRECOMP_NO_INTERPRETER=1` | stop at the first address with no recompiled code instead of interpreting it |
| `PURE_EXIT_AT_FRAME=N`, `PURE_FRAME_LOG=N` | stop at the Nth flip; log every Nth flip (`[pure] frame N`) |
| `PURE_PACED_FROM=N` | (task 034, for the tools) the kernel's clock runs unpaced (patch 0011's `Kernel::set_paced(false)`) from start-up until flip N and is held to real time from flip N on, in any shell; prints `[pure] PURE_PACED_FROM=N: ...` at start-up and `[pure] paced from frame N t=...` at the switch. Headless, the menus before a race take seconds while the race keeps real time: `tools/campaign_sweep.py` sets it to the mode's Cross-hold flip, since its follower steers the race closed loop. The speed-up is real only without a window: a window still presents at the display's rate (the Metal shell waits for a drawable at vsync), so a windowed run's 30-fps menus go at most at the display's flips a second. `0` is paced from the start in any shell; unset (or empty) leaves it to the shell, as before: paced with a window, unpaced without |
| `PURE_SCREENSHOT_DIR=dir PURE_SCREENSHOT_EVERY=N` | BMP of every Nth frame, and where the script's `shot` steps write (`tools/run_boot.py --shots` converts them to PNG); needs a GE backend that runs: windowed, or headless with the Metal (default) or null backend |
| `PURE_INPUT_SCRIPT="700:pad a;1350:pad start;1500:shot name"` | scripted input, frame-indexed; actions `pad a/b/x/y/start/back/dpup/...` (SDL's names: a = Cross, back = Select), `axis NAME VALUE`, `key NAME` (SDL's key names: `Escape`, `Return`, `Down`), `shot NAME`, `quit`; every name and the PSP button it presses are in [docs/controls.md](docs/controls.md) (keyboard layouts, gamepad mapping, dead zone, rebinding in the menu and in settings.ini). In a window it drives a virtual gamepad; in the headless shell (`PURE_SHELL` below) the same file drives the pad directly: `pad`, `axis`, `shot` (the GE backend's picture) and `quit` work, `key`/`mouse`/`click`/`text`/`drop` are reported once and ignored. `PURE_INPUT_LIVE=<file>` (appended lines, read as they come) works in both |
| `PURE_LIST_STUBS=1`, `PURE_STRICT_HLE=1` | list unimplemented imports at start; stop at the first one called |
| `PURE_TRACE_{KERNEL,IO,GE,MPEG,ATRAC,SAS,AUDIO,SAVEDATA,PAD,PACING,SYNC}=1` | framework traces, one subsystem each; `PAD` prints `[pad] buttons 0x... analog X,Y right X,Y` on each change of the pad (the bits and values: [docs/controls.md](docs/controls.md)) |
| `PURE_MALLOC_DEBUG=1` (in `tools/env.sh`) | macOS malloc checks for a single run (task 015): `( export PURE_MALLOC_DEBUG=1; . tools/env.sh; python3 tools/run_boot.py ... )` |
| `PURE_NO_STENCIL_ALPHA=1` | (patch 0004) the renderer stores each draw's fragment alpha and ignores the stencil ops and write masks, as before task 009 (the whole race scene blooms); implies `PURE_NO_STENCIL_BUFFER=1` |
| `PURE_NO_STENCIL_BUFFER=1` | (patch 0006) no Vulkan stencil attachment, as with patch 0004 alone: every stencil test is drawn as ALWAYS and only the zpass REPLACE/ZERO reach the alpha, so the ship shadows (stencil volumes) are missing |
| `PURE_NO_DUAL_SOURCE=1` | (patch 0006) no dual-source blending: a stencil REPLACE under a colour blend that reads the source alpha is stored through the blend constant (exact only where the fragment is opaque); with the stencil attachment on, the alpha is then copied from the stencil before anything reads it |
| `PURE_TRACE_STENCIL_COPY=1` | (patch 0006) a `[render] stencil copied into the alpha of 0x... in frame N (reason)` line for each copy of the stencil into a target's alpha (one per race frame, at the end of the back buffer's pass); the Metal backend prints the same as `[metal] ...` (task 025) |
| `PURE_NO_DEPTH_READBACK=1` | (patch 0008) no depth write-back: guest VRAM under the depth buffer stays as it was (zeros on Vineta K), so the lens flare's CPU depth test always sees open sky and the flare is never occluded, as before task 019. The write-back is on by default for every game on the framework (it has no per-game hook for it), and costs one GPU wait per GE SIGNAL interrupt with a screen-wide depth buffer: one per race frame in Wipeout Pure, none in its frontend |
| `PURE_TRACE_DEPTH_READBACK=1` | (patch 0008) a `[render] frame N signal 0x200: depth of 0x... written back to 0x04110000 stride 512, z MIN-MAX, T ms (GPU wait W ms)` line for each depth write-back; the Metal backend prints the same as `[metal] ...` (task 025) |
| `PURE_GE_BACKEND=metal\|vulkan\|null\|record` | (patch 0009, task 021) the GE backend (docs/ge-backend.md, "What landed"); on macOS metal when unset (our `main()` sets it, D-008, task 028), else vulkan; an empty value means vulkan, and an unknown name falls back to vulkan. `metal` (task 023, `docs/metal-backend.md`) draws natively at 480x272 and passes the three frontend scenes (`tools/frame_regress.sh --backend metal --only lang,title,profile`); since task 024 it lights and fogs 3D draws as the Vulkan backend does (`tools/gerec/metal_check.sh`) and reads the framework's `PURE_NO_LIGHTING`, `PURE_NO_FOG` and `PURE_NO_CULL` as it does; since task 025 it keeps the stencil as alpha (shadow volumes, the bloom's mask), draws the bloom chain, and writes block-transfer sources, read-backs, the frame and the depth (the lens flare's) into guest memory, so it passes the whole suite (`tools/frame_regress.sh --backend metal`). It needs no window: headless (`PURE_NO_RENDER` set) it draws without one, and with the window it hands each picture to the window so the window and the input script's `shot` steps show it (`PURE_METAL_SHELL`). `null` draws nothing, presents black and prints `[render] null backend: frame N, D draws submitted ...` every 600 frames and at exit; it needs no window, so with `PURE_NO_RENDER` set (even to nothing: `--env PURE_NO_RENDER=`) it runs headless with no GPU, and without it the window opens and shows black (scripted input works). `PURE_NO_RENDER` with the vulkan backend still means no rendering at all |
| `PURE_METAL_LOG=1` | (task 023) with `PURE_GE_BACKEND=metal`: a `[metal] frame N draw I ...` line per draw (primitive, vertex count, through or transformed, target address/stride/format, texture and where it was read from, blend, alpha test, depth and stencil test, colour mask, `lit`, `fog`, `cull cw`/`cull ccw` (task 024), scissor) and a line per new target. Every 600 frames and at exit the backend prints its counts either way |
| `PURE_METAL_SHELL=0` | (task 023) with `PURE_GE_BACKEND=metal` and the Vulkan shell's window (there is no hand-over under any other shell): do not hand the pictures to the window shell. The window then stays black and the input script's `shot` steps capture nothing; `PURE_SCREENSHOT_EVERY` captures (`capture_frame`) still work. The hand-over costs a read-back (one GPU wait) a frame |
| `PURE_SHELL=metal\|vulkan\|headless` | (patch 0010, task 026; `metal` task 027) the shell around the GE backend: window, events, pad, input script, interface, presenting (docs/ge-backend.md section 8, "What landed"); on macOS metal when unset (our `main()` sets it with `PURE_GE_BACKEND`, D-008, task 028), else vulkan; an empty value means vulkan, and an unknown name falls back to vulkan. The Vulkan path is `PURE_SHELL=vulkan PURE_GE_BACKEND=vulkan`. `PURE_NO_RENDER` (any value, also empty) always means headless. `headless` has no window and no GPU and takes the pad from `PURE_INPUT_SCRIPT`/`PURE_INPUT_LIVE`, one script frame per flip, so a route runs without a window: `tools/run_boot.py --shell headless --script config/pad_scripts/frontend.txt --frames 2200 out/x.log` (the null backend, no audio) reaches the profile screen in about 1 s (unpaced without a window, patch 0011), and with `--shots DIR` writes the route's `shot` captures (black, from null; the backend's own 480x272 pictures with `--backend metal`). The `vulkan` GE backend needs the vulkan shell: headless with it draws nothing at all, as `PURE_NO_RENDER` always did. Prints `[shell] headless (...)` at start-up. `metal` (`src/host/metal_shell.mm`) is an SDL window with a `CAMetalLayer`: with `PURE_GE_BACKEND=metal` the game runs with no Vulkan or MoltenVK, the window shows the backend's texture letterboxed (no read-back), scripted input, `shot` captures (the window, 960x544 at the default 2x) and the menu (Esc) work as in the Vulkan window; no frame interpolation, Fill aspect, touch controls or texture-pack rows. Prints `[shell] metal: DEVICE, window WxH, vsync` and `[shell] metal (...)` |
| `PURE_GE_RECORD=<file> PURE_GE_RECORD_AT=N PURE_GE_RECORD_FRAMES=M PURE_GE_RECORD_INNER=<name>` | (patch 0009) with `PURE_GE_BACKEND=record`: frames N to N+M-1 (defaults 1 and 3, numbered as the `[render] frame N (D draws)` lines count them) drawn by the inner backend (default vulkan, which needs `PURE_SHELL=vulkan` now that the Metal shell is the default) to a `.gerec` file: every call with the guest memory it read, and each frame's presented image. A `[render] frame N (D draws) recorded: ...` line per frame. `tools/gerec/gerec_dump.py FILE [--summary] [--images DIR]` lists the records and checks the per-frame draw counts |
| `PURE_WATCH_MOVIE=1` | once per flip, while they change: the game's movie object (`DAT_08ab45bc`) and its fields `active`, `ended`, `paused`, reader state, picture-queue capacity, `queued`, `shown` (pictures handed to the renderer), slots (`[pure] movie frame N ...`) |
| `PURE_AUDIO_WAV=<file>` | (task 013) WAV capture of what the game hands to sceAudio (`sceAudioOutputPannedBlocking`, `sceAudioOutputBlocking`, `sceAudioOutputPanned`): each buffer as stereo 16-bit 44.1 kHz with the call's volumes applied, to `<file>.ch<N>.wav` per channel and the clipped sum to `<file>`. Every file is on the virtual clock (sample 0 at time 0; a late or idle channel gets zeros). Read with `tools/wavstats.py` (docs/verification.md, "Audio") |
| `PURE_WATCH_SHIP=1` | (task 007) once per flip during a race, while it changes: the player's race record (`.bss` array of 0x1C0-byte entries, position of entry k at `0x08B72010 + k*0x1C0`): race clock, position, velocity, km/h, track distance, lap, and (task 017) the shield from the ship object (`be::Ship` +0xF8, float, 100 full on the Feisar) (`[pure] ship frame N t=... clock=... pos=... vel=... kmh=... dist=... lap=... shield=...`). PPSSPP reads the same race-record addresses |
| `PURE_WATCH_GRID=1` | (task 032) during a race (while the player's ship object is there), once per flip, every entry of the race-record array, k = 0 to 7, each line when it changes: `[pure] grid frame N k=K clock=C pos=x,y,z vel=vx,vy,vz dist=D lap=L` (the ship probe's race-record fields for each ship; the player's entry is the index of the `player object` line, 7 on a Single Race grid). Eight lines a flip: for recording racing lines (`tools/pp_lines.py --port`), not for long runs |

and is off unless set.
