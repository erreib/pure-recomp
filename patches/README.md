# Patches against the vendored framework

Applied in numeric order by `tools/vendor_setup.sh` (`git apply` inside `vendor/yakumo`). `tools/patches.sh check`
applies the series to a clean checkout of the pinned commit and compares it with the vendor tree;
`tools/patches.sh export NNNN-slug` writes a new patch from the vendor tree's uncommitted changes.

| Patch | Kind | Why |
|---|---|---|

Kinds: Layout constant, Bug, Missing feature, Tooling, Speed. Patches that could go upstream are marked in the Why column.
| 0001-embed-nids-verbatim | Bug | `portablekit_add_game` passes `-DINPUT=a.csv|b.csv` to the shell unquoted when a profile ships `config/nids.csv`; the `|` becomes a pipe. Adds `VERBATIM`. Upstream candidate |
| 0002-ring-not-empty-while-aus-pending | Bug | `sceMpegRingbufferAvailableSize` reported the ring empty while the demuxer still held access units (the audio fetch runs ahead and takes the last packs), so a game that ends a movie on an empty ring (Wipeout Pure) dropped its last 16 pictures and never tore the movie down. Reports one packet short of empty while units are queued. Upstream candidate |
| 0003-framebuffer-texture-prefers-exact-target | Bug | `find_framebuffer_texture` picked the most recently drawn target containing a texture's address; Wipeout Pure's bloom blurs 0x04132000, which lies inside the 0x04110000 target, so the blur sampled never-drawn rows (magenta). Prefer a target starting at the address. Upstream candidate |
| 0004-stencil-as-alpha | Missing feature | The GE state ignored the stencil (0x24, 0xDC, 0xDD) and the write masks (0xE8, 0xE9), and every draw stored its fragment alpha, so Wipeout Pure's bloom mask (stencil REPLACE into the 8888 alpha) was full everywhere and the whole race scene bloomed. Parses them into `DrawCall::stencil`, `color_write_mask`, `alpha_write_mask`; the target's alpha is now written only by the stencil zpass op (REPLACE ref, ZERO; KEEP, no stencil test or masked bits leave it), through the fragment shader or, when the colour blend reads source alpha, the alpha blend factors (exact for ZERO, opaque fragments only for REPLACE); whole masked colour channels are not written. Other stencil functions and INCR/DECR/INVERT are logged once. `PURE_NO_STENCIL_ALPHA=1` restores the old path. Upstream candidate |
| 0005-alpha-test-never-always | Bug | The fragment shader read the GE alpha-test function 1 as NEVER and 0 as "no test", but the GE numbers them like the depth test, 0 NEVER and 1 ALWAYS, so every draw that enables the alpha test with ALWAYS was discarded: on Vineta K that is 268 of 871 draws and 87% of the frame (track, barriers, arches, pillars, sky cube). Tests by the GE numbering, pushes ALWAYS for draws without the test and for clears, and compiles the discard out for ALWAYS instead of NEVER. Applies after 0003 (written before 0004 existed). Upstream candidate |
| 0006-shadow-volumes-and-dual-source | Missing feature | Wipeout Pure's ship shadows are depth-fail stencil volumes (zfail INCR/DECR, colour masked) and a full-screen darkening tested GREATER ref 4, which 0004 drew as ALWAYS over the whole opaque world. Each target's depth image gets a stencil aspect (D32_SFLOAT_S8_UINT, else D24_UNORM_S8_UINT), loaded and stored by the render pass; every draw with the stencil on a 5551/4444/8888 target puts its test, ops, reference, compare mask and write mask (~0xE9) in the pipeline key (`stencil`, `stencil_values`; keys file version 3), and a clear of the alpha REPLACEs the stencil with the clear alpha. The stencil is exact and the alpha (what textures, blends, the display and write-back read) is its copy: after a draw the colour path cannot match (`alpha_follows_stencil`), the stencil is copied into the alpha before the next destination-alpha blend and at the end of the pass (`resolve_stencil_alpha`, 9 quads inside the pass from a fixed vertex slot). REPLACE under a colour blend that reads source alpha uses dual-source blending (`kAlphaDual`, SRC1_ALPHA) when the device has `dualSrcBlend`; the other pipelines use a SPIR-V copy with the second output moved off. `PURE_NO_STENCIL_BUFFER=1` (implied by `PURE_NO_STENCIL_ALPHA=1`) and `PURE_NO_DUAL_SOURCE=1` turn the parts off; `PURE_TRACE_STENCIL_COPY=1` logs each copy. Upstream candidate |
| 0007-free-target-descriptors-before-pool | Bug | `VulkanRenderer::shutdown()` destroyed `descriptor_pool` and only then the render targets, whose `destroy_target` frees each target's two copy descriptor sets (made when the game samples a framebuffer, as Wipeout Pure's bloom does) back to that pool. Under MoltenVK the pool and its sets are heap objects, so `vkFreeDescriptorSets` wrote into freed memory: the "Heap corruption detected, free list is damaged ... Incorrect guard value" abort (or a hang while the crash report was written) after a race's frame exit (task 015). Destroys the targets, the held picture and the interpolation targets before the pool. Upstream candidate |
| 0008-depth-write-back-at-signal | Missing feature | The renderer kept depth in per-target Vulkan images and never stored it in guest VRAM, so Wipeout Pure's lens flare, whose GE SIGNAL 0x0200 handler reads a 4x4 block of the depth buffer around the sun with the CPU (through the 0x04600000 mirror), always read zeros (open sky) and was never occluded. Before a SIGNAL interrupt with a signal function is queued, `write_back_depth` copies the depth aspect of the GE's current colour target into a mapped buffer, runs the frame recorded so far and waits (as `read_back_framebuffer` does), and stores z = depth x 65535 as 16-bit pixels in rows of the depth stride at the depth address (480x272; screen-wide buffers, stride 480 or more, only). Depth images get TRANSFER_SRC usage. About 1 ms a race frame on the M4 Pro, 0.9 of it the GPU wait. `PURE_NO_DEPTH_READBACK=1` turns it off; `PURE_TRACE_DEPTH_READBACK=1` logs each write-back. Upstream candidate (a per-game switch in `GameProfile` would keep the wait off games that never read depth) |
