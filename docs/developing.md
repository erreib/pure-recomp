# Developing pure-recomp

The developer reference: the repository's layout, the tools, the first-time setup and how a build runs. The
player-facing picture is README.md; the state of the work is docs/status.md; the rules every session follows are
CLAUDE.md.

## Layout
| Path | What |
|---|---|
| `config/` | function map, labels, imports, NIDs the framework lacks, the Metal pre-warm list, pad scripts (routes and the sweep's steering tables). Addresses and names only |
| `src/` | ours, built into the game's executable: `profile/` the game's profile and the test hooks, `hle/` the audio capture, `gpu/` the Metal backend, `host/` our `main()` and the Metal shell, `tools/` ge_replay |
| `src/profile/` | `pure_profile.cpp`: `portablekit::game()` (the game's identity, hashes, memory, save folders, the extra HLE calls, the run-control switches); `test_hooks.{hpp,cpp}`: every test-only switch and probe behind one `install` and one `flip` (task 051, docs/verification.md "Test hooks") |
| `src/helpers.hpp` | small helpers more than one source uses, each written once (task 093): `env_on` (a switch read as on or off), `hex`, `load_float` |
| `src/hle/audio_capture.cpp` | `PURE_AUDIO_WAV`: what the game hands to sceAudio, as WAV files on the virtual clock (task 013, docs/fidelity.md "Audio") |
| `src/gpu/` | the Metal GE backend (tasks 023 to 025, `docs/metal-backend.md`): `metal_backend.mm` and the files beside it by concern (Objective-C++ with ARC, registered as `metal`; `docs/metal-backend.md`, "Files"), `shaders/ge.metal` (the MSL with the GE's lighting and fog and the stencil kept as alpha, embedded by the build and compiled at run time: no Xcode needed), `metal_device.mm` (the one Metal device and queue the backend and the shell share), `ge_names.hpp` (the GE names `ge_replay` shares) |
| `src/gpu/models_backend.{hpp,cpp}` | the models backend (task 102, D-025; docs/ge-backend.md "The models backend"), registered as `models` and the default on every platform: it wraps the backend `PURE_GE_MODELS_INNER` names and, with the Video tab's Crowds and people row at Models, draws each quad of a texture `models/models.ini` names as a model from `models/` (the pit marshal today); built on every platform. `WrappingBackend::inner()` is how the Metal shell finds the Metal backend's texture pack host through it |
| `src/host/metal_shell.mm` | the Metal shell (task 027, `PURE_SHELL=metal`, `docs/metal-backend.md` "The Metal shell"): an SDL window with a `CAMetalLayer`, the shared SDL pad, the Metal backend's texture presented directly, the interface on Dear ImGui's Metal backend (`third_party/imgui_metal/`, the 1.92.9b files verbatim); since task 086 the Aspect ratio row's Fill (the backend's targets at the drawable's shape, the game told that shape: `docs/metal-backend.md` "Fill") and `PURE_WINDOW_SIZE` |
| `src/host/pure_main.cpp` | our `main()` (task 022): `PureNative --replay ...` runs ge_replay, anything else the framework's main, compiled as `portablekit_main` (`HOST_MAIN_NAME` in `CMakeLists.txt`), so the game starts as before; on macOS it first sets `PURE_SHELL=metal` when it is unset (task 028, D-008); since task 102 it sets `PURE_GE_BACKEND=models` when unset, on every platform, and `PURE_GE_MODELS_INNER` when unset to the backend that was the default before: metal on macOS (vulkan under the Vulkan shell), vulkan elsewhere |
| `src/tools/ge_replay.cpp` | ge_replay: `PureNative --replay FILE.gerec [--backend NAME] [--out DIR] [--compare] [--tol T] [--max-frac F] [--frames A[-B]] [--cut N] [--a NAME --b NAME [--first-diff]] [--quiet]` feeds a recording to any GE backend outside the game, compares each presented frame with the recorded image (as `tools/imgdiff.py` does) or two backends with each other, and bisects a failing frame to its first differing draw; `--cut N` (task 025) ends the last frame replayed after its Nth draw and presents and captures it there; exit 0 all compared frames pass, 1 one fails, 2 bad file or backend (docs/ge-backend.md, section 7) |
| `src/tools/ge_extract.cpp` | ge_replay's `--extract` (task 101): `PureNative --replay FILE.gerec --extract FRAME --out DIR [--keys K1,K2,...]` replays into a null lane up to frame FRAME (the recording's numbering, as `--frames` takes it) and writes `DIR/frame.obj` and `frame.mtl` (one `o draw_NNNN_<key>` per transformed draw, NNNN counted from 1 as `--cut` counts, vertices in world space: the world matrix applied, the view left out; sprites expanded as the Vulkan renderer expands them; lines and points skipped and counted), `DIR/textures/<key>.png` (every texture the frame binds, through the framework's TextureDumper keyed as the HD pack keys: xxh64, ignoreAddress, ignoreMipmap) and `DIR/frame.json` (the views, the camera's view and projection, the usual world matrix, and per draw its key, primitive, counts, texture, world-space bounds, blend, alpha test, depth, stencil, fog, lighting, culling and a billboard guess); `--keys` keeps only the draws of those keys in frame.obj. Everything it writes is derived from the game: under out/ only (docs/ge-backend.md, section 7) |
| `patches/` | the changes to the vendored framework, one patch per topic, applied in numeric order (`tools/vendor_setup.sh`, `tools/patches.sh`; patches/README.md maps the old numbers tasks 001 to 048 cite) |
| `packaging/` | what the framework's packer reads for the app (task 029, [docs/release.md](release.md)): `release.env`, `THIRD_PARTY_NOTICES.md`, `macos/Wipeout Pure.icns` and `macos/README.txt`, the icon's `icon.png` and `make_icon.py` |
| `third_party/imgui_metal/` | Dear ImGui's Metal renderer backend, the 1.92.9b files verbatim (MIT), for the Metal shell |
| `tools/` | extraction, build, run, measurement, Ghidra and PPSSPP drivers: the tools table below |
| `CMakeLists.txt`, `CMakePresets.json` | the build: the game's executable through `portablekit_add_game`, our sources, the Metal shader's embedding; the presets `arm64` and `arm64-release` with `/usr/bin/clang` |
| `docs/` | status, decisions, the reference docs (one per subsystem), task briefs and their Results under `docs/tasks/` (the record), and under `docs/history/` what the reference docs recorded of each task's runs |
| `ref/` | PPSSPP reference captures (ignored except the README) |
| `.claude/agents/` | the worker and reviewer agents' instructions |
| `disc/`, `disc.iso`, `game/`, `generated/`, `vendor/`, `build/`, `out/`, `ref/*` captures, `ghidra_project/`, `.ccache/` | ignored: game data, generated code, third party, build output (`.gitignore`) |

## First-time setup
```
brew install cmake ninja ccache pkgconf sdl3 molten-vk vulkan-loader vulkan-headers glslang vulkan-validationlayers ghidra
brew install --cask ppsspp-emulator
ln -s "/path/to/Wipeout Pure (USA) (En,Fr,Es) (v2.00).iso" disc.iso
python3 tools/iso_extract.py disc.iso verify && python3 tools/iso_extract.py disc.iso extract disc
tools/check_env.sh
```
Details and machine traps: [docs/setup.md](setup.md). Ghidra: `tools/ghidra_headless.sh import` then `export`.

## Running
`tools/setup_game.sh` lays out `game/` (EBOOT.ELF = the disc's plain BOOT.BIN, `disc.iso`, `ms0/`). `tools/regen.sh`
generates the corpus into `generated/` (85 s) and `tools/build.sh profile` compiles it (8 min cold, seconds after).
`build/arm64/bin/PureNative` runs the game; `tools/run_boot.py` wraps it with a deadline and a folded log. The game
runs under a pty, so a deadline kill loses no output, and the log always ends with the `[run_boot] exit` line.
What a player presses (the keyboard's two layouts, the mouse, the gamepad, rebinding in the Esc menu and in
settings.ini) is in [docs/controls.md](controls.md).

| `tools/run_boot.py` flag | Meaning |
|---|---|
| `--seconds N` | wall-clock deadline, default 60; exit code 124 when it kills the game |
| `--window` | renderer on (headless otherwise: `PURE_NO_RENDER=1`); the shell and backend are the default ones (Metal on macOS) unless named. Silent all the same unless `--sound` (task 034) |
| `--shell vulkan\|metal\|headless` | (task 028) `PURE_SHELL`. `vulkan` and `metal` imply `--window`. `headless` keeps the run headless even with `--script` or `--shots`, sets `PURE_GE_BACKEND=null` unless `--backend` or the environment names a backend; the run is unpaced: `--shell headless --script config/pad_scripts/frontend.txt --shots DIR --frames 2200` reaches the profile screen in about 1 s with the four shots written (black, from null; `--backend metal` draws them) |
| `--backend NAME` | (task 028) `PURE_GE_BACKEND` (`metal`, `vulkan`, `null`, `record`, `models`: the default it replaces, task 102) |
| `--strict` | `PURE_STRICT_HLE=1` |
| `--frames N` | `PURE_EXIT_AT_FRAME=N`, deadline at least N/15 s, exit code 0 when the run ends at that frame |
| `--script FILE` | `PURE_INPUT_SCRIPT` from the file's non-empty, non-`#` lines joined with `;`; implies `--window` unless `--shell headless` (which runs the script without a window) |
| `--shots DIR` | `PURE_SCREENSHOT_DIR`; implies `--window` unless `--shell headless`; after the run each new BMP there gets a PNG beside it (`tools/png.py`) |
| `--every N` | `PURE_SCREENSHOT_EVERY` (default 0 with `--shots`: only the script's `shot` steps write) |
| `--stubs` | `<log>.stubs.txt`: the start-up "Unimplemented imports" list and each `[hle-stub]` call with its `ra` |

and is off unless set.
